# Подключение графики, FX и аудио — Словопад

Версия комплекта 2.0 · 2026-09-05. Передача программисту, а не уже выполненная интеграция.

## 1. Исходная точка

Проверены `godot/project.godot` и `godot/scripts/main.gd` из базового коммита `5401846`. Проект использует 1600×900, `canvas_items`, `gl_compatibility`; отрисовка пока выполняется в одном `Control._draw()`. Поле: 10×16, CELL=44, начало (510,94). `board` хранит буквы, а не типы бонусов. Монет и аудиосервиса в этом коде нет.

Концепты задают стиль и композицию, но не новую математику поля: ширина и число видимых клеток на рисунках не являются спецификацией. Не увеличивать CELL до 64 без пересчёта высоты 16 строк. 64 px — проверочный размер ассета, текущая текстура на поле будет 40 px внутри шага 44.

В этой поставке изменены только `assets/` и `docs/`. Все действия ниже должен выполнить программист. Точные ресурсы перечислены в `asset_registry.md`, аудиособытия и стартовые уровни — в `audio_manifest.json`. Документация Godot `stable` меняется; перед внедрением зафиксировать точную версию редактора/экспортных шаблонов. Здесь выбраны базовые API Godot 4, без зависимости от новых DPITexture, AudioStreamInteractive или GPU trails.

## 2. Контракт файлов и импорта

Префикс `godot/` в Git соответствует `res://` внутри игры.

| Группа | Файл/размер | Настройки первого импорта |
|---|---|---|
| Фон | `assets/backgrounds/background_forest.png`, 1920×1080 RGB | Texture2D, Lossless; при оптимизации сравнить Lossy визуально |
| Плитки | `assets/tiles/tile_*.png`, 256×256 RGBA | Lossless, Fix Alpha Border on, Premult Alpha off |
| Сова | `assets/characters/owl/owl_*.png`, 512×512 RGBA | Аналогично плиткам |
| Монета | `assets/rewards/coin_gold.png`, 256×256 RGBA | Аналогично плиткам |
| Иконки | `assets/ui/icons/icon_*.svg`, 64×64 | Texture2D; для отображения крупнее 64 px увеличить SVG Scale при импорте |
| FX | `assets/fx/particle_*.png`, 64×64 RGBA | Lossless, Fix Alpha Border on, Premult Alpha off |

Фильтрация задаётся в CanvasItem, не старым флагом импорта: Linear, Repeat Disabled. Mipmaps включать после сравнения сильно уменьшенных плиток/совы; тогда выбрать Linear with Mipmaps. Обычный SVG растрируется при импорте, поэтому увеличение SVG-узла само по себе не гарантирует векторную резкость. Основание: [импорт изображений](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_images.html).

Оценка верхнего бюджета RGBA8 без mipmaps для текущих PNG и импортированных SVG — около 14,8 MiB; это расчёт по пикселям, не замер VRAM движка. Не путать размер PNG на диске с памятью текстуры.

## 3. Подключение к существующей отрисовке

На первом шаге сохранить существующую механику и координаты. Загрузить набор `Texture2D` один раз при старте; не вызывать `load()`, создавать узлы или проигрывать звук в `_draw()`.

| Текущая функция | Конкретная замена |
|---|---|
| `_draw_background()` | Один `draw_texture_rect(background, Rect2(Vector2.ZERO, BASE_SIZE), false)`. Убрать процедурные деревья, луну, воду и звёзды, чтобы не дублировать рисунок |
| `_draw_tile()` | В существующем rect нарисовать выбранную Texture2D; затем отдельно букву. Существующую прямоугольную подложку плитки заменить, иначе она будет видна через alpha |
| `_draw_next_piece()` | Та же функция выбора текстуры и тот же inset, что на поле; масштабирование одинаковое по осям |
| `_draw_current_word()` | Собранные буквы на плитках; пустые слоты и знак пропуска остаются кодом |
| `_draw_top_hud()` | Вместо текстовых символов использовать score/ combo/ time/ pause/ settings SVG; число и подпись остаются отдельным текстом |
| `_draw_left_panel()` | `icon_chapter_forest.svg` и `icon_clue_paw.svg`; check/lock без кнопочных подложек |
| `_draw_right_panel()` | `icon_hint.svg`; количество подсказок и весь текст отрисовать отдельно |

Рисовать текстуры через `draw_texture_rect()` допустимо в текущей архитектуре. При изменении состояния вызывать `queue_redraw()`; эти команды исполняются из `_draw()`. Основание: [custom drawing](https://docs.godotengine.org/en/stable/tutorials/2d/custom_drawing_in_2d.html).

При дальнейшем выделении сцен разумны `TileView` (TextureRect + Label), `OwlView`, `FxRoot`, `AudioService`. Это будущая структура, этих узлов сейчас нет. Для декоративных `Control` выставить `mouse_filter = MOUSE_FILTER_IGNORE`, чтобы текстуры не перекрывали обработку мыши.

Не применять двойное масштабирование: текущие `_draw()` и `_screen_to_base()` используют собственный scale/offset поверх viewport. Если добавлять обычные узлы FX, они не наследуют `draw_set_transform()`. Либо перенести графику и FX под один преобразуемый родитель, либо явно преобразовать координаты событий: `screen_position = offset + base_position * scale_factor`. Проверить клики в центре/углах при 1280×720, 1600×900, 1920×1080 и нестандартном окне.

## 4. Выбор плитки и читаемость

Приоритет: реальное специальное состояние (когда появится в модели) → нужная буква → обычный визуальный вариант. Сейчас специальных состояний нет.

Для текущего прототипа оставить синий обычным и золотой для `_is_needed_letter(letter)`. Для разноцветной картинки из концепта можно выбрать детерминированный вариант среди blue/green/red/purple по букве, но это исключительно оформление. Не обещать игроку опасность красной плитки или бонус зелёной, пока этого нет в механике. Золото лучше зарезервировать для цели; существующий `_tile_color()` может выбирать золото для обычных букв — это нужно устранить при интеграции.

Плитки v2: внешняя форма x/y=8, размер 240, radius=31; лицевая зона x=24,y=23,w=208,h=201. При CELL=44 текущий rect имеет 40×40: видимое тело 37,5×37,5. Не добавлять второй крупный прозрачный inset.

Стартовая типографика для 40 px: буква 24–26 px, жирный кириллический шрифт; центр холста (128,124) как оптический ориентир. Белая буква требует тёмной обводки 1–2 экранных px, особенно на золоте/зелёном; альтернатива на золоте — тёмная буква. Сами буквы в PNG не добавлять. Шрифт не входит в эту поставку.

## 5. Сова, монеты и декор

У всех сов один холст 512×512. Ось тела x=256, лапы около y=481. Не делать индивидуальный trim. При желаемой опоре совы в base-space, например (105,820), и стороне холста 200: scale=200/512; верхний левый угол равен `foot_position - Vector2(256,481)*scale`. Это точка для текущей узкой левой полосы; финальную композицию согласовать с шириной панели. У happy крылья занимают почти весь холст — оставить место справа/слева.

Приоритет поз: defeat → chapter_complete/happy → короткий happy после слова → короткий hint → worried → idle. Worried включать по согласованному порогу высоты, например занятость верхних четырёх строк, с гистерезисом. Поза hint длится 1,2 s, happy 0,9 s; это предлагаемые значения. Возвращать позу через состояние, чтобы отложенный таймер не отменил defeat.

`icon_coin.svg` предназначен для счётчика валюты, `coin_gold.png` — для анимации награды. **Счёт остаётся короной.** Сейчас события награды монетами нет. Подключать монеты только после появления транзакции награды; не начислять баланс по окончанию анимации. 3–6 визуальных монет могут обозначать любую сумму, которую задаёт модель. Лист `icon_leaf.svg` — дополнительный декоративный символ, не новая игровая механика.

## 6. FX под текущий рендер

Светящиеся ореолы из концепта не впечены в плитки. Поставлены четыре белые alpha-текстуры, окрашиваемые при использовании: dot, spark, shard, leaf. White используется для корректного tint. В комплекте нет готовых эмиттеров, шейдеров или сцен FX.

Базовый путь: CPUParticles2D для небольших всплесков, Tween для движения/затухания, обычное alpha-смешивание. Для ярких искр можно локально применить CanvasItemMaterial с Add, ограничив число/альфу. Это не требует глобального HDR/bloom. В новых Godot функции Compatibility расширяются; не переносить утверждения об отсутствии Glow на все версии. Наш вариант сознательно не зависит от post-processing и particle trails. [Сравнение рендеров](https://docs.godotengine.org/en/stable/tutorials/rendering/renderers.html), [CanvasItem](https://docs.godotengine.org/en/stable/classes/class_canvasitem.html).

Все значения ниже — стартовые художественные настройки для масштаба 1600×900, не пределы Godot.

| Эффект | Как собрать | Параметры |
|---|---|---|
| Нужная буква | Округлая обводка/ореол отдельным draw или shader на увеличенном quad за плиткой | Gold #FFD65A; пульсация alpha 0,16…0,32, период 1,4 s; максимум 8 активных ореолов |
| След hard drop | 2–3 копии силуэта/короткие Line2D за фигурой | 0,10…0,18 s, alpha до 0,18, затем удалить; не растягивать буквы |
| Ghost | Пунктирный rounded rectangle кодом, лёгкая заливка | Cyan #8CE2FF, обводка 1–2 px; без букв и PNG-панели |
| Фиксация фигуры | `particle_shard.png`, 4–6 частиц на событие | 0,18–0,3 s; размер 2–4 px; скорость 25–55 px/s |
| Очистка линии | `particle_spark.png`, по 1–2 частицы из бывшей клетки + тонкая линия кодом | 0,3–0,5 s; 3–6 px; скорость 45–100 px/s; не больше 24 частиц за запуск |
| Сбор нужной буквы | Одна копия плитки/буквы летит к целевому слоту | 0,35–0,5 s; исходная позиция взята до collapse |
| Готовое слово | 12–18 spark, зелёный/золотой, один импульс масштаба слова | 0,6 s; размер 4–7 px; scale слова 1→1,05→1 |
| Победа главы | 18–24 leaf, зелёный tint, край экрана | 0,9–1,4 s; вращение ±80°/s; размер 6–10 px |
| Монеты | Sprite2D с coin_gold, дуга к счётчику | 3–6 спрайтов по 20–28 px; 0,5–0,8 s; stagger 0,06 s |
| Светлячки | 6–10 dot только у краёв | 2–3 px, alpha 0,1…0,35, скорость 2–6 px/s; отключаемо |

Эмиттеру one-shot задать `one_shot=true`, `explosiveness=1`, `emitting=false`, `local_coords=false`; при запуске установить position и вызвать `restart()`. События не должны перезапускать один и тот же занятый эмиттер: использовать небольшой пул. Размер белой текстуры 64 px, поэтому частица 4 px требует scale≈0,0625. Завершение — `finished`, возврат в пул. [CPUParticles2D](https://docs.godotengine.org/en/stable/classes/class_cpuparticles2d.html).

Для Tween: создавать через `create_tween()`, привязывать к живому узлу; при повторной анимации той же property останавливать старый tween. Не переиспользовать завершённый Tween. [Tween](https://docs.godotengine.org/en/stable/classes/class_tween.html).

Общий стартовый лимит — 96 активных частиц и 6 монет; при переполнении пропускать декор. Reduced FX выключает ореолы, следы и фоновые частицы, сохраняя целевой золотой цвет, ghost и подтверждение действия. FX в пределах поля клиповать отдельно; монеты и полёт буквы к левому HUD — поверх поля без этого клипа.

## 7. События: где запускать

Сначала изменить модель, затем отправить одно событие представлению. Проверка `game_over` в `_draw()` не является событием и не должна запускать звук.

| Место в текущем коде | Событие и защита |
|---|---|
| `_handle_key()` / `_handle_click()` | ui_click — только реальный клик по действию, не любой клик по экрану |
| `_try_move()` | piece_move только после успешного пользовательского горизонтального сдвига. Не озвучивать каждый шаг `_hard_drop()` и автогравитации |
| `_try_rotate()` | piece_rotate один раз в ветке успешного kick; invalid — если все варианты не подошли, с cooldown |
| `_lock_piece()` | piece_lock один раз после записи фигуры; FX из сохранённых координат клеток |
| `_clear_full_lines()` | До `_collapse_rows()` сохранить строки, буквы и позиции источников; после расчёта отправить line_clear один раз для всего набора |
| `_collect_letter()` | Получатель — конкретный индекс слота, не только символ: в слове возможны повторения. Добавить в событие slot_index до изменения/сброса слова |
| `_complete_word()` | Сохранить старое слово/слоты до `_reset_word_state()`. word_complete один раз; при финальном слове chapter_complete имеет приоритет над обычным сигналом успеха |
| `_use_hint()` | hint только после выбора кандидата и уменьшения charges; при пустом списке/нуле charges не проигрывать успешную подсказку |
| Обе ветки установки `game_over=true` | defeat один раз на переходе false→true |
| Пауза/настройки/сброс | Закрыть активные представления, очистить пулы/очередь; не допускать отложенных наград из предыдущей партии |

Важно: существующий `_collect_letter()` возвращает bool. Для анимации понадобится расширить результат/событие индексом; не вычислять этот индекс после `_complete_word()`, когда слово уже сменилось. Модель должна обновляться сразу, а полёт буквы остаётся визуальным представлением результата.

## 8. Музыка и звуки

Поставлены 1 OGG и 12 WAV, все CC0. Происхождение, исходные имена, хеши и обработка — `audio_sources.md`. Музыка — один подготовленный цикл около минуты, SFX — короткие сигналы; победа главы — короткое подтверждение, не отдельная музыкальная фанфара.

Импорт: WAV 16-bit mono 44,1 kHz, PCM, Loop Disabled, Normalize off, Trim off (подготовка уже выполнена). OGG stereo 44,1 kHz, Loop on, Loop Offset=0. Не включать 8-bit. WAV подходит для коротких повторяемых звуков, OGG экономит место для музыки. [Импорт аудио](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_audio_samples.html).

Создать шины Master → Music и SFX. В `audio_manifest.json` gain применяется на плеере, а пользовательский уровень — на шине: не умножать один и тот же стартовый gain дважды. Сохранять независимо music_enabled, sfx_enabled, music_volume, sfx_volume. Для отключения — `AudioServer.set_bus_mute()`, для громкости — `set_bus_volume_db()`; индекс получать по имени и проверять >=0. [AudioServer](https://docs.godotengine.org/en/stable/classes/class_audioserver.html).

AudioService: один непозиционный `AudioStreamPlayer` для музыки и пул из 8 непозиционных плееров для SFX. Загрузить streams один раз. Для каждого события проверить cooldown по `Time.get_ticks_msec()`, взять свободный плеер, присвоить stream/bus/volume_db и вызвать `play()`. При переполнении разрешить отбросить move/click, но оставить канал для hint/defeat/success. Переназначение stream останавливает звук этого плеера — не использовать один общий плеер для всех событий. [AudioStreamPlayer](https://docs.godotengine.org/en/stable/classes/class_audiostreamplayer.html).

Музыку зациклить свойством `AudioStreamOggVorbis.loop`, не обработчиком `finished`. Loop offset=0; BPM и beat_count оставить 0, поскольку файл подготовлен как полный цикл без музыкальной сетки. Для индивидуального изменения stream сделать duplicate, чтобы не менять общий ресурс. [AudioStreamOggVorbis](https://docs.godotengine.org/en/stable/classes/class_audiostreamoggvorbis.html).

Контракт сервиса: `play_sfx(event_id)`, `start_music()`, `set_music_enabled(bool)`, `set_sfx_enabled(bool)`, `set_suspended(reason, bool)`. Последний метод хранит набор причин pause/focus/ad; музыку возобновлять лишь при пустом наборе и включённой пользовательской настройке. Не возвращать звук автоматически, если пользователь выключил его во время рекламы. На сбросе остановить SFX/очистить cooldown; музыку не начинать заново без необходимости. Переходы громкости: 0,2–0,4 s; параметры — отправная точка для прослушивания в игре.

Для будущего Web-экспорта запускать первый звук после пользовательского ввода. Sample playback имеет ограничения AudioEffects; этот пакет не требует reverb/компрессора во время игры. Проверить паузу/возврат фокуса и два полных цикла в целевом браузере. [Web audio](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html).

## 9. Приёмка интеграции

1. Импортировать в закреплённой версии Godot без ошибок и внешних ресурсов SVG.
2. Проверить каждую кириллическую букву на пяти цветах при 40 px; золото отличимо от обычных вариантов.
3. Сменить пять поз совы без прыжка лап/масштаба; happy не обрезан панелью.
4. Проверить hard drop: один lock, одна очистка группы строк, одна награда, без звукового треска от цикла сдвигов.
5. Проверить слово с повторяющейся буквой, финальное слово, подсказку без зарядов, проигрыш и сброс во время FX.
6. Убедиться, что музыка повторяется без щелчка/провала; прослушать её вместе с SFX и скорректировать mix. Числовая проверка аудио не заменяет прослушивание.
7. Пауза/фокус/реклама/настройки должны сохранять независимые выключатели Music/SFX.
8. Проверить мышь и клип FX на четырёх размерах окна, лимит частиц и Reduced FX.

Статус этой передачи: проверены файлы, SVG-рендер, размеры, alpha и технические параметры аудио. Запуск игры с новыми ассетами и прослушивание итогового микса не выполнены: код интеграции не изменялся.
