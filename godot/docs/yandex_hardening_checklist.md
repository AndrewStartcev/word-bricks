# Словопад — Yandex Games hardening checklist

Ветка: `fix/yandex-hardening`

Этот чеклист закрывает этап стабилизации платформенного слоя перед UI-проходом и Web QA.

## Что изменено

### Реклама

- Fullscreen и rewarded всегда завершают runtime-flow даже при `onError`.
- Повторный `onClose` после `onError` не создаёт двойное событие закрытия.
- На открытии рекламы звук принудительно suspend'ится отдельной причиной `yandex_ad`.
- Rewarded во время активной партии ставит локальный gameplay на паузу и корректно возобновляет его после закрытия.
- Platform pause/resume и ad pause могут приходить в любом порядке и не должны оставлять игру навсегда на паузе.
- Fullscreen запрашивается только после завершённого уровня и явного действия игрока.
- Введён собственный cooldown fullscreen:
  - минимум 180 секунд активного gameplay;
  - минимум 2 завершённых уровня;
  - cooldown сбрасывается после каждого завершённого запроса, включая `wasShown=false`.

### Cloud save

- Local save остаётся основным fallback.
- Cloud sync работает с debounce 2 секунды.
- Один cloud request выполняется за раз.
- Если локальное состояние изменилось, пока предыдущий request был in-flight, новая ревизия остаётся dirty и отправляется следующим запросом.
- Ошибка `player.setData()` не теряет сохранение: включён exponential backoff 3 → 6 → 12 → 24 → 30 секунд.
- Для конфликта между устройствами используются:
  1. `local_saved_at` / cloud `saved_at`;
  2. `cloud_revision` как tie-breaker и fallback для старых сохранений без timestamp.
- `saved_at` обозначает время изменения локального состояния, а не позднее время отправки debounce-запроса.

### Account selection / авторизация

- Отслеживается `ACCOUNT_SELECTION_DIALOG_OPENED`.
- Пока Yandex показывает выбор анонимного/авторизованного прогресса, регулярный cloud sync приостанавливается.
- После `ACCOUNT_SELECTION_DIALOG_CLOSED` Player и cloud data перечитываются базовым bridge.
- Runtime получает `account_changed` и заново разрешает конфликт local/cloud.
- Активный уровень не заменяется облачным прогрессом посреди партии: текущая сессия остаётся local-first до следующей точки сохранения.

## Что проверить в Godot локально

- [ ] Проект открывается без parser errors.
- [ ] Native запуск работает без Yandex SDK и не создаёт бесконечные cloud retry.
- [ ] Главное меню открывается.
- [ ] Старт уровня работает.
- [ ] Pause / Resume работает до и после рекламной интеграции.
- [ ] Сброс прогресса не ломает save schema.

## Что проверить в Yandex draft `debug-mode=16`

### SDK lifecycle

- [ ] SDK инициализирован.
- [ ] i18n определяется через `ysdk.environment.i18n.lang`.
- [ ] `LoadingAPI.ready()` приходит после готовности игрового UI.
- [ ] `GameplayAPI.start()` активен только во время реальной партии.
- [ ] `GameplayAPI.stop()` работает в меню, картах, комиксах, pause/result/finale.

### Pause / audio

- [ ] Смена вкладки останавливает gameplay и звук.
- [ ] Возврат во вкладку корректно продолжает незавершённую партию.
- [ ] Fullscreen полностью глушит звук.
- [ ] Rewarded полностью глушит звук и не позволяет игровому полю продолжать падение фигур за рекламой.
- [ ] После закрытия рекламы звук и gameplay возвращаются ровно один раз.

### Fullscreen

- [ ] После 1-го короткого уровня fullscreen не запрашивается.
- [ ] До 180 секунд активной игры fullscreen не запрашивается.
- [ ] После выполнения обоих условий запрос возможен только на экране результата.
- [ ] `wasShown=false` не блокирует переход к следующему уровню.
- [ ] SDK `onError` не блокирует переход к следующему уровню.

### Rewarded

- [ ] Награда выдаётся только после `onRewarded`.
- [ ] Закрытие без reward ничего не выдаёт.
- [ ] `onError` возвращает пользователя в игру.
- [ ] Повторный callback не удваивает награду / close-flow.

### Cloud saves

- [ ] После изменения прогресса `setData()` вызывается не мгновенно на каждый input, а после debounce.
- [ ] Повторные локальные изменения во время одного cloud request не теряются.
- [ ] Искусственный `setData()` error приводит к retry.
- [ ] Retry не идёт чаще заданного backoff.
- [ ] Более новое облачное сохранение побеждает более старое локальное.
- [ ] Более новое локальное сохранение не затирается старым облаком.
- [ ] Старые save без `local_saved_at` продолжают сравниваться по revision.

### Account selection

- [ ] При открытии Yandex account-selection dialog cloud sync приостанавливается.
- [ ] После закрытия запрашивается новый Player.
- [ ] После выбора облачного прогресса меню/карта отображают выбранный прогресс.
- [ ] Если пользователь авторизовался во время активной партии, текущий раунд не перезапускается внезапно.

## Перед merge в main

- [ ] Native fallback проверен.
- [ ] Yandex draft lifecycle проверен.
